หน้าที่ 1 · จ่ายค่าแนะนำ

แถบเดียว เส้นเดียว: ตั้งจ่ายได้เลย → รอคุณตรวจสอบ → รอฝ่ายบัญชีโอน
แล้วจบที่ไทล์สีเขียว "โอนแล้ว" ซึ่ง **ไม่ใช่ขั้น** แต่เป็นประตูออกไปหน้ารายงาน
(เส้นประ ไม่มีเลขขั้น ไม่มีป้าย "กำลังดู") — เพราะโอนแล้วคือไม่มีอะไรให้ทำต่อ

จุดที่ต้องระวังที่สุด: **หน่วยของแถวเปลี่ยนกลางทาง**
· ขั้น 1 แถว = คน (รวมค่าคอมทุกรายการของเขา ยอดคิดสดจาก ledger)
· ขั้น 2-3 แถว = ใบคำขอ (ยอดแช่แข็งตอนสร้างใบ บัญชีเป็น snapshot)
จุดเปลี่ยนคือตอนกดตั้งจ่าย — คนกลายเป็นใบ
จึงมีป้าย "หน่วย: คน / หน่วย: ใบคำขอ" กำกับหัวลิสต์ทุกขั้น ไม่ปล่อยให้เดา

ขั้น 2 มีเฉพาะใบที่ "ตัวแทนกดขอเอง" — ใบที่คุณตั้งจ่ายเองข้ามขั้นนี้ไปเลย
(ถือว่าอนุมัติแล้วตั้งแต่ตอนกด) นี่คือเหตุผลที่รอบจ่ายเคยต้องมีอยู่:
มันมีกล่องขาเข้าที่หน้าตั้งจ่ายมองไม่เห็น
ของใหม่ที่ขอตัดสินใจ: ติ๊กหลายใบแล้วบันทึกโอนทีเดียว (ขั้น 3)

ตอนนี้ปุ่ม "บันทึกการโอนเงิน" กดได้ทีละใบ และเด้ง prompt ถามเลขอ้างอิงทีละใบ
แต่ฝ่ายบัญชีโอนมาเป็นรอบ แล้วแจ้งกลับเป็นชุด — UI จึงควรรับเป็นชุดได้

แถบดำของขั้น 3 จึงมีช่องเลขอ้างอิงในตัว ไม่ใช่ popup
(ใส่ครั้งเดียวติดทุกใบที่ติ๊ก หรือเว้นว่างก็ได้)

ข้อควรรู้: ต้องเพิ่ม endpoint ฝั่ง backend (ตอนนี้มีแค่ทีละใบ)
ถ้าไม่อยากเพิ่ม บอกได้ ผมทำทีละใบเหมือนเดิมแต่ย้าย prompt มาเป็นช่องกรอกในแถว

ความหมายของการติ๊กต่างกันตามขั้น — ขั้น 1 ติ๊ก = "จะจ่ายคนนี้"
ขั้น 3 ติ๊ก = "คนนี้โอนแล้ว" — ปุ่มบนแถบดำจึงเปลี่ยนคำตามขั้นเสมอ
และสีก็เปลี่ยน (น้ำเงิน = ตั้งจ่าย, เขียว = ปิดรายการจริง)

หน้าที่ 2 · รายงานการจ่าย

กฎข้อเดียวของหน้านี้: **ไม่มีปุ่มที่เขียนข้อมูล** ไม่มีอนุมัติ ไม่มีบันทึกโอน
ถ้าเห็นอะไรที่อยากแก้ ให้กลับไปหน้าที่ 1 — ถ้าวันหนึ่งมีปุ่มโผล่มาที่นี่
แปลว่าเรากำลังสร้างสองหน้าที่แทนกันได้อีกรอบ

สถานะที่นี่เป็น **ชิปตัวกรอง** ไม่ใช่การ์ดใหญ่แบบหน้าที่ 1 โดยตั้งใจ
สองหน้าจะได้ไม่หน้าตาเหมือนกันอีก — และเพราะที่นี่สถานะคือ "เงื่อนไขการค้นหา"
ไม่ใช่ "ขั้นที่ต้องทำ"

ที่มา · ช่วงวันที่ · เลือกได้ว่าจะนับจากวันที่โอน หรือวันที่ขอ · ชื่อผู้รับ
