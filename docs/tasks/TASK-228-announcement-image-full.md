# TASK-228 — รูปในป๊อปอัปข่าวสารโดนครอป

**Status:** implemented · frontend 144 passed (14 files) · **Owner:** ag-lead
**คำขอ:** human (พร้อมภาพหน้าจอ) — *"ตัวข่าวสาร คำนวณ ภาพความสูง ความยาวของภาพ ให้เต็มรูป และไม่ล้นพื้นที่ทำงาน ของหน้าจอด้านหลัง"*

---

## 1. สาเหตุ — บรรทัดเดียว

`AnnouncementModal.vue`:

```js
displayStyle === 'full_screen' ? 'h-72 object-cover' : 'h-56 sm:h-64 object-cover rounded-t-3xl'
```

กล่องความสูง**ตายตัว** 224 / 256 / 288 px แล้วให้ `object-cover` เติมเต็มกล่องด้วยการ **ครอปส่วนที่เกินทิ้ง**

รูปแบนเนอร์ทุกใบจึงถูกตัดให้เหลือความสูงเท่ากันหมด ไม่ว่าสัดส่วนจริงจะเป็นเท่าไร
ในภาพที่ human ส่งมา ส่วนที่หายคือแถบล่าง **"โซนดีล GENESENN"** — ซึ่งคือสิ่งที่ประกาศนั้นมีไว้เพื่อบอก

## 2. ทางแก้

```js
displayStyle === 'full_screen' ? '' : 'rounded-t-3xl'
```
```html
<img class="w-full h-auto block bg-surface-chip" :class="imageClasses" />
```

`w-full` + `h-auto` และ**ไม่มี `object-*` เลย** — เบราว์เซอร์คำนวณความสูงจากสัดส่วนจริงของไฟล์
ไม่มีทางครอป

**ทำไมไม่ใช่ `object-contain`** — contain ไม่ครอปก็จริง แต่ยัง**คงกล่องความสูงตายตัวไว้**
แล้วใส่รูปแบบ letterbox ข้างใน = เห็นรูปครบ แต่มีแถบว่างบน-ล่าง การถอดความสูงออกไปเลย
ได้ทั้งไม่ครอปและไม่มีแถบว่าง

`block` ตัดช่องว่าง baseline ของ inline image ที่จะทำให้เห็นเส้นสีการ์ดคั่นบาง ๆ
`bg-surface-chip` ให้พื้นที่รูปมีสีตามธีมระหว่างรอโหลด แทนที่จะแฟลชสีการ์ด

## 3. "ไม่ล้นพื้นที่ทำงาน" ถูกกันไว้ที่การ์ด ไม่ใช่ที่รูป

human เลือก (จาก AskUserQuestion) ว่า **ไม่จำกัดความสูงรูป แสดงเต็มสัดส่วนจริงเสมอ**

โมดัลยังล้นจอไม่ได้อยู่ดี เพราะ**การ์ด**ถือ `max-h-[85vh]` / `max-h-[92vh]` คู่กับ `overflow-y-auto`
อยู่แล้ว — รูปสูงแค่ไหนก็ทำให้ *เนื้อหาเลื่อน* ไม่ใช่ *โมดัลโต*

**ข้อแลกที่ human รับแล้ว:** ถ้ารูปเป็นแนวตั้งสูงมาก หัวข้อกับเนื้อหาจะอยู่ใต้ขอบจอ ต้องเลื่อนลงดู

## 4. ขอบเขต — เฉพาะป๊อปอัป

human เลือกให้แก้เฉพาะ `AnnouncementModal.vue`
`AnnouncementBanner.vue` (แถบข่าวบนหน้า Home / สินค้า / ข่าวสารทั้งหมด) ยังใช้ `object-cover` เหมือนเดิม
— ตรงนั้นเป็นการ์ดพรีวิวในกริดที่ความสูงเท่ากันคือสิ่งที่ต้องการ

## 5. เทสต์ที่เพิ่ม — ไฟล์ใหม่ 12 เทสต์

**คอมโพเนนต์นี้มี 4 display style, ผู้เรียก 3 ที่ และ *ไม่มี spec เลย*** — นั่นคือเหตุผลที่
`object-cover` อยู่รอดมาตั้งแต่ TASK-075 จนกว่าจะมีคนส่งภาพหน้าจอมา

เทสต์ยืนยัน **กฎ** ไม่ใช่ชื่อ utility (restyle ได้อิสระตราบใดที่รูปยังเห็นครบ):

| เทสต์ | ยืนยันอะไร |
|---|---|
| `never crops the image` × 4 style | ไม่มีทั้ง `object-cover` และ `object-contain` |
| `pins no fixed height` × 4 style | utility ตระกูล `h-*` ต้องมีแค่ `h-auto` ตัวเดียว (กัน `sm:h-64` ที่แอบกลับมา) |
| `spans the full width` | `w-full` — สัดส่วนจริงเป็นตัวกำหนดความสูง |
| `keeps the card capped to the viewport` | คู่ตรงข้ามของการไม่จำกัดรูป: กันล้นที่การ์ด |
| อีก 2 ตัว | ไม่มีประกาศ / ประกาศไม่มีรูป → ไม่เรนเดอร์ `<img>` |

**พิสูจน์ว่าเทสต์จับบั๊กจริง:** รันชุดนี้กับโค้ดเดิม → **8 ใน 12 ล้ม** รันกับโค้ดใหม่ → ผ่านหมด
