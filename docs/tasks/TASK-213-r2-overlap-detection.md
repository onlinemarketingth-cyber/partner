## 1. บั๊กที่เจอในข้อมูลจริง

สินค้า **"ทดสอบค่าคอม แบ่งให้ หัวหน้าทีม"** มีกฎคอมมิชชั่น **3 ใบมีผลพร้อมกัน**:

| อัตรา | มีผลตั้งแต่ | ถึง |
|---|---|---|
| 100 บาท | 17 ส.ค. 2569 | — |
| 150 บาท | 17 ส.ค. 2569 | 31 ส.ค. 2569 |
| 180 บาท | 17 ส.ค. 2569 | 31 ส.ค. 2569 |

`CommissionService::resolveCommissionRule()` เรียง `ORDER BY effective_from DESC`
แล้ว `->first()` — **แต่ทั้งสามใบวันเริ่มเท่ากัน** เมื่อค่าที่ใช้เรียงเสมอกัน
SQL ไม่รับประกันลำดับ ผลคือดีลที่ปิดวันนี้ได้ **100 หรือ 150 หรือ 180 บาท
แบบทำนายไม่ได้** และ ledger แก้ย้อนหลังไม่ได้ (BR-4)

## 2. ทำไมของเดิมกันไม่ได้

`assertNoOverlap()` มีอยู่ทั้งใน `CommissionRuleService` และ
`CommissionOverrideRuleService` และ**จะบล็อกทั้งสามใบนี้ถ้าสร้างวันนี้** —
แต่มันทำงาน**ตอนเขียนเท่านั้น**

สามใบนี้เป็นข้อมูลที่ถูกต้องในวันที่สร้าง เพราะตอนนั้นขอบเขตยังรวม
`cert_tier_id` อยู่ → หนึ่งใบต่อหนึ่ง tier ไม่ชนกัน **ADR-035 (18 ส.ค. 2569)
ตัด `cert_tier_id` ออกจากการหาอัตรา** ทำให้แถวที่เคยแยกกันได้อย่างถูกต้อง
กลายเป็นแถวที่ชนกันย้อนหลัง — ตัวกันตอนเขียนมองไม่เห็นเหตุการณ์นี้

**บทเรียน:** invariant ที่บังคับตอนเขียนอย่างเดียว จะขาดทันทีที่นิยามของ
"ขอบเขต" เปลี่ยน การตรวจจึงต้องอยู่ตรงที่**อ่านข้อมูลเก่า**ด้วย

## 3. สิ่งที่เพิ่ม (frontend เท่านั้น ไม่แตะหลังบ้าน)

`CommissionPlansView.vue`

**ตัวตรวจ** — จัดกลุ่มกฎที่ **active วันนี้** ตาม scope key เดียวกับที่
เซิร์ฟเวอร์ใช้ resolve (`product:<id>` / `category:<id>` / `company`)
กลุ่มไหนมีมากกว่า 1 แถว = ชนกันทั้งกลุ่ม · ฝั่งหัวหน้าทีมใช้หลักเดียวกัน
แต่คีย์ด้วย cert tier ของหัวหน้า

**แสดงผล 3 จุด**

1. **แท็บภาพรวมสินค้า** — ปุ่มแดง "อัตราซ้อนทับ N → ดูรายการ" บนแถบสรุป
   ขึ้นแม้ไม่มีสินค้าไหน resolve ไปที่ scope นั้น (เช่นค่าเริ่มต้นทั้งบริษัทซ้ำกัน 2 ใบ)
   เพราะการชนนั้นมีอยู่จริง และจะกัดสินค้าตัวแรกที่ตกมาถึงมัน
2. **การ์ดสินค้า** — ไฟแดง "มีอัตราซ้อนทับกัน 3 รายการในขอบเขตเดียวกัน —
   ระบบจะหยิบอันไหนก็ได้" · **จัดอันดับไว้รองจาก "ไม่มีอัตราเลย" เท่านั้น**
   เพราะการมีหลายอันไม่ได้ปลอดภัยกว่าการไม่มี — เงินยังออก แค่ออกในจำนวน
   ที่ไม่มีใครเลือก
3. **แท็บกฎคอมมิชชั่น** — แบนเนอร์แดงด้านบน + ป้าย **"ซ้อนทับ"** และขอบแดง
   บนแถวที่ชนกันจริง ๆ · ตัวเลขบนแท็บภาพรวมบอกว่า*มีปัญหา* แต่มีแค่รายการนี้
   ที่บอกได้ว่า**ต้องลบแถวไหน** — และปุ่มลบอยู่บนแถวนั้นเลย

## 4. ขอบเขตของตัวตรวจ (สิ่งที่มัน **ไม่** จับ)

- ตรวจเฉพาะกฎที่ **active วันนี้** — กฎที่จะไปชนกันในอนาคตยังไม่ขึ้นเตือน
  (ตัวกันตอนเขียนดูแลกรณีนั้นอยู่แล้ว ยกเว้นถ้ามีการเปลี่ยนนิยามขอบเขตอีก)
- ตรวจเฉพาะ **บริษัทที่เลือกอยู่บนหัวจอ** และเฉพาะตอนมีคนเปิดดู —
  ถ้าต้องการกวาดทุกบริษัทพร้อมกัน ควรทำเป็น artisan command (ยังไม่ได้ทำ)
- **ไม่ลบข้อมูลให้อัตโนมัติ** — ใบไหนคืออัตราที่ถูกต้องเป็นการตัดสินใจเชิงธุรกิจ
  (BR-7) ไม่ใช่สิ่งที่ระบบควรเดา

## 5. สิ่งที่ human ต้องทำกับข้อมูลชุดนี้

ลบให้เหลือใบเดียวสำหรับ "ทดสอบค่าคอม แบ่งให้ หัวหน้าทีม" (ถ้าเป็นข้อมูล
ทดสอบก็ลบทิ้งได้ทั้งหมด) — กดลบได้จากแถวที่ติดป้าย "ซ้อนทับ" โดยตรง

**ควรตรวจด้วยว่ามีดีลไหนของสินค้านี้ปิดไปแล้วระหว่าง 17–19 ส.ค. 2569 หรือยัง** —
ถ้ามี ค่าคอมที่ลงไปแล้วอาจเป็น 100/150/180 อันไหนก็ได้ และแก้ไม่ได้แล้ว

## 7. QA

1. เปิดแท็บ **กฎคอมมิชชั่น** → ต้องเห็นแบนเนอร์แดง "พบอัตราซ้อนทับกัน 3 รายการ"
   และ 3 แถวของ "ทดสอบค่าคอม" ติดป้าย **ซ้อนทับ** ขอบแดง
2. แถวอื่น (Vital Blueprint, ค่าเริ่มต้นทั้งบริษัท, หัวหน้าทีม Basic) **ต้องไม่ติดป้าย**
3. ไปแท็บ **ภาพรวมสินค้า** → ปุ่มแดง "อัตราซ้อนทับ 3 → ดูรายการ" กดแล้วพากลับมาที่รายการ
4. การ์ด "ทดสอบค่าคอม" ต้องขึ้นไฟแดงเรื่องซ้อนทับ (ไม่ใช่เรื่องไม่มีอัตรา)
5. ลบจนเหลือใบเดียว → แบนเนอร์ ป้าย และปุ่มแดงต้องหายทั้งหมด การ์ดกลับเป็นเขียว
6. ลองสร้างกฎซ้อนทับใหม่ → **เซิร์ฟเวอร์ต้องปฏิเสธ (422)** ตั้งแต่แรก
   ตัวตรวจนี้มีไว้สำหรับข้อมูลเก่าเท่านั้น
