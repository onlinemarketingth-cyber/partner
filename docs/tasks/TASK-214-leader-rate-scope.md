# TASK-214 — อัตราหัวหน้าทีมแยกรายสินค้าได้ และเลิกผูกกับ cert tier

**Status:** implemented (2026-08-19) · **Owner:** ag-lead
**คำสั่งที่ปลดล็อกงานนี้ (human, 2026-08-19):**
> "อัตราหัวหน้าทีมยังผูกกับ cert tier ไหม → **ไม่ต้องผูก**"
> "ลำดับ สินค้า > หมวดหมู่ > ทั้งบริษัท เหมือนอัตราตัวแทนเป๊ะ ๆ ใช่ไหม → **ตามที่คุณเสนอ**"

นี่คือ T6 ในแผน `PLAN-product-commission-one-stop.md` และเป็นคำขอตั้งต้นจริง ๆ
ที่ค้างมาตั้งแต่ *"แยกสินค้า แยกบริษัท ที่ต่างกันได้ทั้งหัวหน้าทีม"*

---

## 1. เปลี่ยนอะไร

**เดิม:** `commission_override_rules` มี `company_id` + `manager_cert_tier_id`
อัตราเลือกจาก **cert tier ของหัวหน้า** และใช้กับ**ทุกสินค้าเหมือนกันหมด**

**ใหม่:** มี `product_id` + `product_category_id` (nullable ทั้งคู่)
อัตราเลือกจาก **สินค้า > หมวดหมู่ > ค่าเริ่มต้นทั้งบริษัท** — โครงเดียวกับ
`resolveCommissionRule()` เป๊ะ ๆ

## 2. `manager_cert_tier_id` **ไม่ได้ถูกลบ**

เก็บคอลัมน์ไว้ แค่เลิกอ่านตอน resolve — ปฏิบัติแบบเดียวกับที่ ADR-035 ทำกับ
`commission_rules.cert_tier_id` เป๊ะ ๆ **การลบทิ้งจะทำลายหลักฐานเดียวที่บอกว่า
แถวเก่าแต่ละใบเคยหมายถึงอะไร** ซึ่งเป็นข้อมูลที่คนต้องใช้ตัดสินว่าใบไหนควรอยู่รอด
ตอนรวมแถว · คอลัมน์กลายเป็น nullable เพราะแถวใหม่ไม่มีอะไรจะใส่

หน้าจอจะแสดงกำกับไว้บนแถวเก่าว่า *"(เดิมตั้งไว้ที่ tier X — ไม่ถูกใช้แล้ว)"*

## 3. สิ่งที่ **ไม่** เปลี่ยน และผมจงใจไม่แตะ

**หัวหน้าที่ยังไม่ผ่าน cert tier ใดเลย ยังไม่ได้รับ override เหมือนเดิม**

คำสั่งที่ได้รับคือเรื่อง **อัตรา** ไม่ใช่เรื่อง **สิทธิ์** และการตัดเช็คนี้ออกจะ
เปลี่ยนว่า *ใครได้เงิน* ไม่ใช่แค่ *ได้เท่าไหร่* — คนละขนาดผลกระทบกันมาก

ที่สำคัญกว่านั้น: การคงไว้**สอดคล้องกับ ADR-035 พอดี** ซึ่งเขียนไว้เองว่า
certification คือ *"a binary access gate, never a rate multiplier"* — งานนี้
เอา multiplier ออก และเก็บ gate ไว้ ตรงตามที่ ADR เขียน

> ถ้าต้องการให้หัวหน้าที่ยังไม่มี cert ได้ override ด้วย บอกได้ — เป็นสวิตช์แยก

## 4. ผลข้างเคียงที่ต้องจัดการ: แถวเก่าชนกัน

บริษัทที่เคยตั้งอัตราแยกตาม tier (Basic 1% / Intermediate 1.5% / High 2%)
มีแถวที่**ถูกต้องในวันที่สร้าง** แต่พอเลิกอ่าน tier แล้วทั้งสามใบตกไปอยู่ scope
เดียวกัน (ค่าเริ่มต้นทั้งบริษัท) active พร้อมกัน → **จ่ายเท่าไหร่ทำนายไม่ได้**

นี่คือกลไกเดียวกับบั๊กที่คุณเจอเมื่อกี้ทุกประการ — และเป็นเหตุผลที่ TASK-213 r2
มีตัวตรวจซ้อนทับอยู่แล้วก่อนหน้านี้

**เครื่องมือ:** `php artisan commission:collapse-override-tiers [--dry-run]`

- อัตราทุก tier **เท่ากันอยู่แล้ว** → รวมให้อัตโนมัติ เก็บใบเก่าสุดไว้
  (ไม่ใช่การตัดสินใจ เป็นเลขคณิต) — ไม่ถาม
- อัตรา **ต่างกัน** → พิมพ์ทุกใบออกมาแล้ว **ถาม** ว่าใบไหนอยู่รอด
  ผมไม่เลือกให้ "เก็บอันสูงสุด" มั่วพอ ๆ กับ "เก็บอันต่ำสุด" ทั้งคู่คือการ
  แต่งตัวเลขขึ้นมาแล้วใส่เสื้อคลุมว่า migration (BR-7)
- ช่วงวันที่ **ไม่ทับกัน** → ไม่ใช่ความกำกวม เป็นประวัติที่ถูกต้อง ไม่แตะ
- รันซ้ำได้ไม่มีผลเสีย

**ต้องรันบน production ก่อนหรือหลัง migrate ก็ได้** — migration ไม่ทำให้ข้อมูล
เปลี่ยนความหมาย (ทุกแถวเดิมเป็น "ค่าเริ่มต้นทั้งบริษัท" อยู่แล้วในทางปฏิบัติ)
แต่ **ต้องรันก่อนมีดีลใหม่ปิด** ถ้าบริษัทไหนมีหลาย tier

## 5. บั๊กที่เจอระหว่างทาง — silent truncation

`GET /commission-override-rules` และ `GET /commission-rules` ทั้งคู่ `->paginate()`
ที่ 15 แถว ในขณะที่หน้าแอดมินอ่านแต่ `data` ไม่เคยอ่าน `meta`

พออัตราแยกรายสินค้าได้ จำนวนแถวจะทะลุ 15 ทันทีสำหรับแคตตาล็อกขนาดกลาง และ
**แถวที่ 16 จะหายจากหน้าจอเงียบ ๆ ทั้งที่ยังเป็นตัวที่จ่ายเงินอยู่**

แก้เป็น `->get()` ทั้งคู่ (เหตุผลและวิธีเดียวกับ `BrandController` ใน TASK-202)
ตารางพวกนี้เป็น config ที่คนพิมพ์เอง ไม่ใช่ข้อมูลที่โตตามปริมาณธุรกรรม

## 9. QA

1. แผนคอมมิชชั่น → กฎคอมมิชชั่น → **+ เพิ่มอัตราหัวหน้าทีม** → ต้องเห็นช่อง
   **ขอบเขต** (ไม่ใช่ Cert tier) → เลือก "ตามสินค้า" → เลือกสินค้า → 2.5% → บันทึก
2. แถวใหม่ต้องขึ้นว่า **"สินค้า: <ชื่อ>"** ไม่ใช่ "ทุกสินค้าในบริษัท"
3. แท็บภาพรวม → การ์ดสินค้านั้น ช่อง "หัวหน้าทีมได้" ต้องขึ้น **2.50% · สินค้า: <ชื่อ>**
   ส่วนสินค้าอื่นยังเป็นอัตราค่าเริ่มต้นทั้งบริษัท
4. แถวเก่าที่เคยตั้งตาม tier ต้องขึ้นกำกับ **"(เดิมตั้งไว้ที่ tier Basic — ไม่ถูกใช้แล้ว)"**
5. ลองเพิ่มอัตราหัวหน้าทีมซ้ำ scope เดิม ช่วงเวลาทับกัน → ต้องได้ 422
6. **ทดสอบเงินจริง:** ปิดดีลของสินค้าที่มีอัตรารายสินค้า → ledger ของหัวหน้า
   ต้องเป็น 2.5% ของราคา ไม่ใช่อัตราค่าเริ่มต้น
7. หัวหน้าที่ยังไม่ผ่าน cert ใดเลย → ต้อง**ไม่มีแถว** ledger (ไม่ใช่แถว 0 บาท)
