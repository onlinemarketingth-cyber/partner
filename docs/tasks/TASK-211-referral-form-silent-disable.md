# TASK-211 — "บันทึกสินค้าไม่ได้" ในหน้าลูกค้า (frontend ตัวแทน)

**Status:** fixed (2026-08-19) · **Owner:** ag-lead · **Type:** UX bug
**File:** `frontend/src/views/ClientsView.vue` — "+ เพิ่มสินค้าที่สนใจ"

## 1. รายงาน

> "หน้า frontend บันทึกสินค้าไม่ได้" — human, 2026-08-19, พร้อมสกรีนช็อต
> iPhone 14 Pro Max + DevTools Network

## 2. อาการจริง vs สิ่งที่ผู้ใช้เห็น

**ไม่ได้พัง.** ช่อง **สาขา ว่าง** และปุ่ม บันทึก ผูก `disabled` ไว้กับ
เงื่อนไขเดียวกับที่ handler ใช้:

```html
:disabled="creatingReferral || !referralForm.product_id || !referralForm.branch"
```
```ts
if (!selectedClientId.value || !referralForm.value.product_id || !referralForm.value.branch) return
```

กดแล้วจึง **ไม่เกิดอะไรเลย** — ไม่ยิง request, ไม่ขึ้นข้อความ. ยืนยันจาก
Network panel ในสกรีนช็อต: ไม่มี `POST /referrals` เลยแม้แต่ครั้งเดียว.

ธีมมืด + `disabled:opacity-50` บนปุ่มสีแบรนด์ = ความต่างที่ตาแทบไม่อ่านว่า
"ปิดใช้งาน" ฟอร์มมี 3 ช่อง ช่องที่ขาดไม่ใช่ช่องที่เพิ่งแตะ ผู้ใช้จึงสรุปได้
ทางเดียวว่าระบบบันทึกไม่ได้ — ซึ่งถูกต้องตามที่เห็น

**สาขาเป็นฟิลด์บังคับจริง** ไม่ใช่ข้อจำกัดที่ frontend คิดเอง —
`StoreReferralRequest::rules()` กำหนด `'branch' => ['required', ...]` สำหรับ
เส้นทางตัวแทนที่ล็อกอิน (คอลัมน์ nullable เพื่อ public checkout ของ TASK-136
เท่านั้น ตามคอมเมนต์ในกฎนั้น) จึงต้อง **บอกให้ชัด ไม่ใช่ผ่อนกฎ**

## 3. การแก้

1. ปุ่ม บันทึก disable เฉพาะตอน `creatingReferral` — การกดต้อง **ไปถึง**
   `submitReferral()` เพราะนั่นคือสิ่งที่ทำให้เกิดข้อความ
2. `submitReferral()` ตรวจทีละช่องและตั้ง `referralFormError` เป็นภาษาไทยที่
   ระบุช่อง (`กรุณาเลือกสินค้า` / `กรุณากรอกสาขา`) แทน `return` เงียบ ๆ
   — เป็น ref ของตัวเอง ไม่ใช้ `errorMessage` ระดับ drawer เพื่อให้ข้อความ
   แสดงอยู่ในกรอบฟอร์มที่มันพูดถึง
3. เพิ่ม label + เครื่องหมาย `*` บน **สินค้า** และ **สาขา**, ระบุ
   **เวลาที่สะดวกนัด (ไม่บังคับ)** ให้ชัด — บอกก่อนกรอก ไม่ใช่หลังกดปุ่ม
4. ช่องสาขาขึ้นขอบแดงเมื่อเป็นช่องที่ขาด, placeholder เปลี่ยนจาก `สาขา`
   (ซ้ำกับ label) เป็นตัวอย่างจริง `เช่น สาขาสีลม`
5. `branch` ถูก `.trim()` ทั้งตอนตรวจและตอนส่ง — เดิมเว้นวรรคล้วนผ่าน guard
   แล้วไปโดน 422 ที่เซิร์ฟเวอร์

# ภาคผนวก — สาขาเป็นฟิลด์ไม่บังคับ (คำสั่งเพิ่มเติม 2026-08-19)

> "คุณเอา * validate ออกจากสาขา" — human

การถอด `*` ออกจากหน้าจออย่างเดียวจะได้ 422 จากเซิร์ฟเวอร์แทน เพราะ
`StoreReferralRequest` บังคับ `branch` อยู่ จึงต้องแก้ให้ตรงกันทั้งสองฝั่ง

## A. แก้อะไรบ้าง

1. **Backend** — `StoreReferralRequest::rules()`
   `'branch' => ['required', ...]` → `['nullable', 'string', 'max:255']`
   คอลัมน์ `referrals.branch` เป็น nullable มาตั้งแต่ TASK-134a จึงไม่ต้อง
   migrate. คอมเมนต์เดิมที่เขียนว่า "STAYS REQUIRED, on purpose … agents
   still know their branch" ถูกแทนที่ด้วยเหตุผลใหม่และอ้างคำสั่งนี้
2. **Frontend** — `ClientsView.vue`: ป้ายเป็น "สาขา (ไม่บังคับ)", ตัดการตรวจ
   และกรอบแดงของช่องนี้ออก, ส่ง `undefined` เมื่อว่าง (ไม่ใช่ `''`) เพื่อให้
   เก็บเป็น **NULL** จริง — ป้ายในไปป์ไลน์อ่านค่าด้วย `branch ?? ...`
   สตริงว่างจะเรนเดอร์เป็นช่องว่าง ไม่ใช่ข้อความสำรอง
3. **สินค้า ยังบังคับอยู่** (`*` และข้อความ "กรุณาเลือกสินค้า" คงเดิม) —
   คำสั่งระบุเฉพาะสาขา
4. **Test ใหม่** `ReferralTest::test_agent_may_submit_a_referral_without_a_branch`
   ปักหมุดกฎนี้ไว้ ไม่ให้ `required` แอบกลับมา

## B. ผลข้างเคียงที่ต้องแก้พ่วง — ป้าย "ผ่านลิงก์ออนไลน์"

เดิม `branch IS NULL` ถูกใช้เป็น **ตัวชี้วัดโดยปริยาย** ว่า "ขายผ่านลิงก์
แชร์สินค้า" (TASK-136) เพราะมีแค่ทางนั้นทางเดียวที่ปล่อยให้ NULL ได้ — ตาราง
`referrals` ไม่มีคอลัมน์ `source` ที่บอกที่มาจริง ๆ

พอตัวแทนเว้นสาขาว่างได้ ข้อสันนิษฐานนี้พังทันที และหน้าไปป์ไลน์จะ **ติดป้าย
ผิด** ว่ารายการที่ตัวแทนสร้างเองมาจากลิงก์ออนไลน์ จึงเปลี่ยนข้อความสำรองเป็น
`ไม่ระบุสาขา` ทั้ง 4 จุด:

- `frontend/src/design-system/components/PipelineBoard.vue` (2 จุด)
- `frontend-admin/src/views/ReferralPipelineManagementView.vue` (2 จุด)

**ของที่หายไป:** ตอนนี้แยกไม่ออกแล้วว่ารายการไหนมาจากลิงก์แชร์ ถ้าต้องการ
ข้อมูลนี้กลับมา ต้องเพิ่มคอลัมน์ `referrals.source` (enum: agent / share_link
/ affiliate) แล้วให้ `ProductShareCheckoutService` กับ `ReferralService`
ประทับค่าเอง — เป็นงานแยก ไม่ได้ทำในนี้ เพราะมันคือการเพิ่มข้อมูลใหม่
ไม่ใช่การเดาจากช่องว่าง
