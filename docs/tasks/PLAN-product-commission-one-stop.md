# แผน — ทำให้หน้าสินค้า (รายบริษัท) ตั้งค่าคอมได้ครบในที่เดียว โดยไม่ซ้ำซ้อน

**วันที่:** 2026-08-19 · **ผู้เขียน:** ag-lead · **สถานะ:** ข้อเสนอ รอสั่งงาน
**หน้าจอ:** `/product-catalog/products/:id/edit` → แท็บ **คอมมิชชั่น**
**ที่มา:** human — "ตัว หน้า Product รายบริษัท ทำอย่างไรให้ Setup ได้ครบถ้วนและไม่ซ้ำซ้อน"

---

## 0. ก่อนอื่น — ผมเขียนผิดไว้ในเอกสารก่อนหน้า ขอแก้

TASK-213 §เฟส 3 ผมเขียนว่า *"เหลือประตูเข้า `commission_rules` 2 ทาง"*
**ผิดครับ ยังเหลือ 3 ทาง** ผมนับพลาดหน้านี้ไป:

| # | ที่ | ทำอะไรได้ |
|---|---|---|
| 1 | แผนคอมมิชชั่น → อัตราค่าคอม | ทุกขอบเขต (บริษัท/หมวดหมู่/สินค้า) + ต่ออายุ |
| 2 | แผนคอมมิชชั่น → Wizard | รายสินค้า **% เท่านั้น** |
| 3 | **หน้าสินค้า → แท็บคอมมิชชั่น** | รายสินค้า + ต่ออายุ + วันหมดอายุ |

ทั้งสามเขียนตาราง `commission_rules` เหมือนกัน แต่เป็น **โค้ดคนละชุด 3 ชุด** —
นั่นคือสาเหตุที่ความสามารถไม่ตรงกันตั้งแต่แรก (wizard ทำบาทไม่ได้, ฟอร์มใน
แคตตาล็อกเดิมทำหมวดหมู่ไม่ได้) และเป็นหัวใจของงานนี้

---

## 1. "ครบถ้วน" สำหรับสินค้า 1 ตัว คืออะไร

ไล่จากโค้ดที่จ่ายเงินจริง (`CommissionService`) สินค้าจะจ่ายได้ถูกต้อง ต้องครบ 8 ข้อ:

| # | สิ่งที่ต้องมี | ตอนนี้ตั้งที่ไหน | อยู่ในแท็บคอมมิชชั่นไหม |
|---|---|---|---|
| 1 | **ราคาสินค้า** (ถ้าคิดเป็น %) | หน้าสินค้า → ทั่วไป | ✗ คนละแท็บ |
| 2 | **แผนคอมของสินค้านี้** (สืบทอด/override) | หน้าสินค้า → ทั่วไป | ✗ คนละแท็บ |
| 3 | **รูปแบบอัตรา (%/บาท)** | หน้าสินค้า → คอมมิชชั่น | ✓ |
| 4 | **อัตราตัวแทนผู้ขาย + ช่วงเวลา** | 3 ที่ (ดู §0) | ✓ |
| 5 | **อัตราต่ออายุ** | หน้าสินค้า → คอมมิชชั่น | ✓ |
| 6 | **โหมดจ่ายหัวหน้าทีม** (Additive/Deductive) | หน้าสินค้า → คอมมิชชั่น | ✓ (โชว์เฉพาะแผน Affiliate) |
| 7 | **อัตราหัวหน้าทีม** | แผนคอมมิชชั่น — **ระดับบริษัทเท่านั้น** | ✗ **แยกรายสินค้าไม่ได้เลย** |
| 8 | **โครงสร้างแผน** (Binary/Matrix/Stairstep/Generation) | แผนคอมมิชชั่น — ระดับบริษัท | ✗ ไม่มีแม้แต่การแจ้งสถานะ |

**สรุปช่องว่าง:** ข้อ 1–2 อยู่ผิดแท็บ · ข้อ 4 มีโค้ดซ้ำ 3 ชุด · ข้อ 7 **ทำไม่ได้จริง ๆ**
(ติด schema) · ข้อ 8 เงียบสนิท — สินค้าที่ใช้ Matrix แต่บริษัทยังไม่ตั้งโครงสร้าง
จะดูเหมือนตั้งค่าครบทั้งที่ชั้นบนจะไม่ได้เงินเลย

## 2. หลักการที่ผมอยากให้ทีมยึด

### 2.1 "ครบถ้วน" ≠ "แก้ได้ทุกอย่างจากที่นี่"

แบ่งของเป็น **3 ชั้น** และปฏิบัติต่างกัน:

| ชั้น | ตัวอย่าง | ทำอย่างไรบนหน้าสินค้า |
|---|---|---|
| **A — ของสินค้านี้จริง ๆ** | ราคา, แผน, รูปแบบอัตรา, อัตรา, ต่ออายุ, โหมด Additive | **แก้ได้เต็มที่ตรงนี้** |
| **B — ของบริษัท ที่สินค้านี้พึ่งพา** | โครงสร้าง Matrix/Binary/Generation/อันดับ, อัตราหัวหน้าทีม | **แสดงสถานะ + ลิงก์ออก ห้ามแก้ตรงนี้** |
| **C — ของแพลตฟอร์ม** | เพดานอัตรา | แสดงเป็นข้อจำกัดตอนกรอกเท่านั้น (มีแล้ว) |

**เหตุผลที่ชั้น B ห้ามแก้ตรงนี้:** แอดมินที่กำลังแก้สินค้า 1 ตัว แล้วเปลี่ยน
ความลึก Matrix จากหน้านั้นได้ จะไม่รู้ตัวว่าเพิ่งเปลี่ยนเงื่อนไขการจ่ายของ
สินค้าอีก 40 ตัวพร้อมกัน ความสะดวกไม่คุ้มกับความเสียหาย — แต่การ**ไม่บอก
เลยว่ามันยังไม่ได้ตั้ง**ก็แย่พอกัน จึงต้องแสดงสถานะเสมอ

### 2.2 ไม่ซ้ำซ้อน = โค้ดชุดเดียว หลายทางเข้า

ตอนนี้ 3 ทางเข้า = **3 implementation** วิธีแก้ไม่ใช่การตัดทางเข้าทิ้ง
(หน้าสินค้าควรมีจริง ๆ) แต่คือ **สกัดเป็น component เดียวแล้ว mount 2 ที่**:

```
design-system/components/CommissionRateEditor.vue   ← ของใหม่ ชุดเดียว
   ├─ mount ที่ แผนคอมมิชชั่น  → scope เลือกได้ (บริษัท/หมวดหมู่/สินค้า)
   └─ mount ที่ หน้าสินค้า      → scope ปักไว้ที่ product นี้ (ซ่อนช่องขอบเขต)
```

เข้าคนละประตู แต่เป็นฟอร์มเดียวกัน กฎเดียวกัน หน่วยเดียวกัน ตัวกันเพดาน
เดียวกัน — แก้บั๊กครั้งเดียวได้ทั้งสองที่ และเพิ่มความสามารถครั้งเดียวได้ทั้งสองที่
**Wizard ก็เรียก component เดียวกันนี้** จึงได้ตัวเลือก "บาท" ฟรี

## 3. หน้าตาที่เสนอ — แท็บคอมมิชชั่นของหน้าสินค้า

```
┌ ความพร้อมจ่ายค่าคอมของสินค้านี้ ───────────────────────────── ● ยังไม่พร้อม ┐
│ ✓ ราคา 8,900 บาท          ✓ แผน: พันธมิตร (Affiliate)                      │
│ ✓ อัตราตัวแทนผู้ขาย 3.00%   ● อัตราหัวหน้าทีม: ยังไม่มี  [ไปตั้งค่า →]        │
│ ⚠ มีอัตราซ้อนทับ 2 รายการ  [ดูรายการ →]                                    │
└────────────────────────────────────────────────────────────────────────────┘

┌ ชั้น A — ตั้งได้ที่นี่ ─────────────────────────────────────────────────────┐
│ แผนคอมมิชชั่นของสินค้านี้  [สืบทอดจากบริษัท ▾]   ← ย้ายมาจากแท็บ "ทั่วไป"    │
│ ราคา  [8,900] บาท                                ← มิเรอร์จากแท็บ "ทั่วไป"   │
│ รูปแบบอัตรา  [% ของยอดขาย ▾]  · โหมดจ่ายหัวหน้าทีม [Additive ▾]           │
│                                                                            │
│ อัตราตัวแทนผู้ขาย        <CommissionRateEditor scope="product">            │
│ อัตราหัวหน้าทีมของสินค้านี้  <CommissionRateEditor scope="product"          │
│                              recipient="leader">   ← ปลดล็อกหลังเฟส 4      │
└────────────────────────────────────────────────────────────────────────────┘

┌ ชั้น B — ค่าระดับบริษัท (อ่านอย่างเดียว) ──────────────────────────────────┐
│ แผนนี้ใช้ commission_override_rules ระดับบริษัท · ตั้งไว้แล้ว 1 อัตรา       │
│ ⓘ มีผลกับทุกสินค้าที่ใช้แผนเดียวกัน                    [ไปแก้ที่แผนคอม →]   │
└────────────────────────────────────────────────────────────────────────────┘
```

**การ์ดความพร้อมใช้ตรรกะเดียวกับแท็บภาพรวมของแผนคอมมิชชั่น** (`productReadiness`
+ `conflictCountFor` ที่เพิ่งเขียนใน TASK-213) — สกัดออกเป็น composable
`useCommissionReadiness()` แล้วใช้ร่วมกัน ไม่เขียนกฎซ้ำ มิฉะนั้นสองหน้าจะ
ตอบไม่ตรงกันภายในเดือนเดียว

## 5. สิ่งที่ต้องตัดสินใจก่อนเริ่ม T6 (BR-7 — ผมไม่ตัดสินให้)

**คำถามที่ 1 — อัตราหัวหน้าทีมยังผูกกับ cert tier ของหัวหน้าไหม**
ADR-035 (18 ส.ค.) ตัด cert tier ออกจากอัตราของตัวแทนไปแล้ว ด้วยเหตุผลว่า
"ผ่านข้อสอบมากกว่า ไม่ควรแปลว่าได้ค่าคอมสูงกว่า" — เหตุผลเดียวกันนี้ใช้กับ
หัวหน้าทีมได้ไหม?

- **ถ้าตัดออก:** ฟอร์มเหลือ 4 ช่อง · แต่ต้อง**รวมแถวเดิมที่แยกตาม tier** ซึ่ง
  เป็นการตัดสินใจว่า "อัตราไหนอยู่รอด" (แบบเดียวกับที่ ADR-035 §3 ต้องทำ
  ด้วย artisan command แบบถาม-ตอบ)
- **ถ้าคงไว้:** ไม่ต้อง migrate ข้อมูล แต่ระบบจะมีสองมาตรฐานอยู่ในหน้าเดียวกัน
  และต้องเขียนอธิบายให้ชัดว่าทำไมคิดคนละแบบ

**คำถามที่ 2 — ลำดับความสำคัญเมื่ออัตราหัวหน้าทีมมีทั้งรายสินค้าและรายบริษัท**
ผมเสนอให้ใช้ลำดับเดียวกับอัตราตัวแทนเป๊ะ ๆ (**สินค้า > หมวดหมู่ > ทั้งบริษัท**)
เพราะการมีสองลำดับในระบบเดียวคือหลุมที่ไม่มีใครจำได้ — ขอแค่ยืนยัน

## 6. สิ่งที่แผนนี้ **ไม่** ทำ

- **ไม่ย้ายการตั้งค่าระดับบริษัทมาไว้หน้าสินค้า** — ดู §2.1
- **ไม่ตัดหน้าแผนคอมมิชชั่นทิ้ง** — ยังจำเป็นสำหรับค่าเริ่มต้นทั้งบริษัท,
  หมวดหมู่ และภาพรวมข้ามสินค้า หน้าสินค้าตอบได้แค่ "สินค้าตัวนี้"
- **ไม่แตะการคำนวณเงิน** ยกเว้น T6 ที่เพิ่มขั้นการ resolve — และแถวเดิมต้อง
  ให้ผลเท่าเดิมทุกกรณี (T8 เป็นคนยืนยัน)
- **ไม่ทำ artisan command กวาดอัตราซ้อนทับทุกบริษัท** — เสนอไว้ใน TASK-213 r2
  ยังไม่ได้สั่งทำ
