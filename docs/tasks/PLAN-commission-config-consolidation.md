# ส่วนที่ 2 — แต่ละอันทำงานต่างกันอย่างไร

## 2.1 ลำดับการหาค่า ณ ตอนจ่าย

เมื่อดีลถึงสถานะ **ชำระเงินครบ** ระบบทำตามลำดับนี้:

```
1. เช็คว่าตัวแทนผ่าน cert tier ไหม        → ไม่ผ่าน = ไม่จ่ายอะไรเลย
2. หาอัตราฐาน: สินค้า > หมวดหมู่ > ทั้งบริษัท   → ไม่เจอ = ไม่จ่ายอะไรเลย
3. คิดจากราคา ณ วินาทีที่จ่าย (รวมโปรโมชั่นราคา)
4. เขียนแถวของตัวแทนผู้ขาย (แบ่งกับตัวแทนร่วมถ้าเปิดสวิตช์)
5. จ่าย "ชั้นบน" ตาม **แผนของสินค้านั้น** — ยิงได้แค่ทางเดียว ไม่ซ้อนกัน
```

**ข้อสำคัญ:** ขั้นที่ 2 เหมือนกันทุกแผน — `commission_rules` คือฐานเสมอ
สิ่งที่ต่างกันคือ **ขั้นที่ 5** เท่านั้น

## 2.2 ขั้นที่ 5 ต่างกันอย่างไร

| แผน | จ่ายชั้นบนอย่างไร | อ่านอัตราจากไหน | ลึกแค่ไหน |
|---|---|---|---|
| **Unilevel (มาตรฐาน)** | ไต่สาย `manager_id` ขึ้นไป จ่ายทุกคนที่มีอัตรา | `commission_override_rules` (ตาม cert tier ของ**หัวหน้าแต่ละคน**) | ไม่จำกัด |
| **พันธมิตร (Affiliate)** | จ่าย**หัวหน้าชั้นเดียว**เหนือขึ้นไป | `commission_override_rules` (ตารางเดียวกับ Unilevel) | 1 ชั้น |
| **Binary** | ไม่จ่ายทันที — สะสมยอดซ้าย/ขวา แล้วจ่ายตามรอบ | `commission_binary_settings` | — |
| **Matrix** | ไต่ผัง matrix ขึ้นไป จ่ายตามอัตราของชั้นนั้น | `commission_matrix_level_rates` | ตาม `depth` |
| **อันดับ (Stairstep)** | จ่าย**ส่วนต่าง**ระหว่างอันดับหัวหน้ากับอันดับลูกทีม | `agent_ranks.rate_value` | หยุดเมื่อเจอ breakaway |
| **Generation** | นับเฉพาะคนที่ถึงอันดับ breakaway เป็น "เจน" | `commission_generation_rules` | ตาม `max_generation_depth` |

## 2.3 ความต่างที่ทำให้สับสนที่สุด

**Unilevel กับ Affiliate ใช้ตารางอัตราเดียวกัน** (`commission_override_rules`)
แต่จ่ายคนละแบบ (ทั้งสาย vs ชั้นเดียว) และ **Affiliate ยังมีโหมด Additive/Deductive**
ที่ตั้งอยู่คนละหน้า (หน้าแก้สินค้า) — ในขณะที่แท็บชื่อ "พันธมิตร (Affiliate)"
ในหน้าแผนคอมมิชชั่น **ไม่มีอัตราให้กรอกเลย** มีแค่ช่วงเวลา attribution

> คนที่อยากตั้งค่าคอมหัวหน้าทีมสำหรับสินค้าแบบ Affiliate ต้องแตะ **3 หน้า**:
> อัตราที่ `/product-catalog` → โหมดจ่ายที่หน้าแก้สินค้า → แผนที่หน้าบริษัทหรือหน้าสินค้า
> และ**ไม่มีอะไรบนแท็บ "พันธมิตร (Affiliate)" บอกเรื่องนี้เลย**

# ส่วนที่ 3 — ปัญหาที่เจอจากการตรวจ

## 3.1 ของเดียวกัน แก้ได้ 3 ที่ ความสามารถไม่เท่ากัน

`commission_rules` เขียนได้จาก **#1, #2, #8, #10** — แต่:

- **#2 เท่านั้น** ที่ตั้งขอบเขต **หมวดหมู่** และ **ค่าเริ่มต้นทั้งบริษัท** ได้
- **#1 (wizard)** บังคับ **% เท่านั้น** — สินค้าที่ล็อกเป็นบาทเข้า wizard ไม่ได้
- **#8** ทำได้แค่รายสินค้า

คนใช้ไม่มีทางรู้ว่าฟอร์มไหนทำอะไรได้มากกว่ากัน

## 3.2 ค่าคอมหัวหน้าทีม **แยกรายสินค้าไม่ได้**

นี่คือสิ่งที่คุณขอโดยตรง (*"แยกสินค้า แยกบริษัท ที่ต่างกันได้ทั้งหัวหน้าทีม"*)
ตอนนี้ `commission_override_rules` มีแค่ `company_id` + `manager_cert_tier_id`

- แยก **บริษัท** ได้ ✓
- แยก **สินค้า / หมวดหมู่** ได้ ✗ — **ต้องแก้ schema**
- กรอกเป็น **บาท** ได้ ✗ ใน UI (API รองรับแล้ว)

## 3.3 อัตราหัวหน้าทีมยังผูกกับ cert tier ทั้งที่อัตราตัวแทนเลิกผูกไปแล้ว

ADR-035 (18 ส.ค. 2569) ตัด cert tier ออกจากการหาอัตราฐาน เพราะ
"ผ่านข้อสอบมากกว่า ไม่ควรแปลว่าได้ค่าคอมสูงกว่า" — แต่ **อัตราหัวหน้าทีม
ยังคงเลือกจาก cert tier ของหัวหน้าอยู่** เหตุผลเดิมยังไม่ถูกทบทวน

## 3.4 ตั้งค่าผิด = ไม่จ่ายเงินอย่างเงียบสนิท (13 ทาง)

จากการอ่านโค้ด service ทั้งหมด พบทางที่ระบบ **ไม่จ่ายและไม่บอกใคร** อย่างน้อย 13 ทาง
ทั้งหมดจงใจให้ดีลเดินต่อได้ (ไม่ block) แต่ **ไม่มีหน้าจอไหนเตือนเลย** ที่สำคัญ:

| อาการ | ผลลัพธ์ |
|---|---|
| ไม่มีกฎคอมของสินค้า/หมวดหมู่/บริษัท | **ทั้งดีลไม่มีใครได้เงิน** มีแค่ log |
| ตัวแทนยังไม่ผ่าน cert tier | **ทั้งดีลไม่มีใครได้เงิน** |
| หัวหน้ายังไม่ผ่าน cert tier | หัวหน้าคนนั้นถูกข้าม |
| สินค้าเป็น Matrix แต่บริษัทยังไม่ตั้ง Matrix | ชั้นบนไม่ได้เลย |
| สินค้าเป็น Generation แต่ยังไม่ตั้งความลึก | ชั้นบนไม่ได้เลย |
| อันดับหัวหน้าเป็น % แต่ของลูกทีมเป็นบาท | ข้ามชั้นนั้น (ลบกันไม่ได้) |

**นี่คือจุดที่ UI ช่วยได้มากที่สุด** — มากกว่าการจัดเมนูใหม่

## 3.5 เพดานอัตราแพลตฟอร์มไม่มีหน้าจอ

`PUT /platform/commission-cap` มีอยู่ แต่แอดมิน UI **อ่านอย่างเดียว** — จะแก้ต้องยิง API เอง
ทั้งที่เพดานนี้บล็อกการบันทึกกฎรายสินค้าอยู่ (และ**ไม่บล็อก**กฎหมวดหมู่/ทั้งบริษัท — ช่องโหว่ที่ตั้งใจ)

# ส่วนที่ 4 — ข้อเสนอ

## หลักการ 4 ข้อ

1. **บ้านเดียว** — ทุกอย่างที่เป็น "เงินที่จ่ายให้ใคร เท่าไหร่" อยู่ที่ `/commission-plans`
   หน้าอื่นเหลือแค่ลิงก์ทางลัด ไม่มีฟอร์มซ้ำ
2. **แยกด้วย "ใครได้เงิน" ไม่ใช่ "ตารางไหนใน DB"** — คนใช้คิดเป็น
   *ตัวแทนผู้ขายได้เท่าไหร่ / หัวหน้าทีมได้เท่าไหร่* ไม่ได้คิดเป็นชื่อตาราง
3. **ขอบเขตเป็นแกนเดียวกันทุกอัตรา** — ทั้งบริษัท / หมวดหมู่ / สินค้า
   ใช้ลำดับเดียวกัน อธิบายครั้งเดียว ใช้ได้ทั้งของตัวแทนและของหัวหน้าทีม
4. **ความซับซ้อนต้องขอถึงจะเห็น** — Binary/Matrix/Stairstep/Generation
   ซ่อนไว้จนกว่าจะมีสินค้าใช้แผนนั้นจริง

## โครงหน้าจอใหม่ — `/commission-plans` 4 แท็บ

```
บริษัท: [Thai Life ▾]   ← ตัวเลือกเดียวจาก header (TASK-208) ทั้งหน้าตามนี้

┌ ภาพรวม ─┬─ อัตราค่าคอม ─┬─ โครงสร้างแผน ─┬─ ตั้งค่าทั่วไป ─┐
```

### แท็บ 1 — ภาพรวม (หน้าแรก)

ตารางรายสินค้า **1 บรรทัด = 1 สินค้า** เห็นครบในหน้าจอเดียว:

| สินค้า | แผน | ตัวแทนได้ | หัวหน้าทีมได้ | สถานะ |
|---|---|---|---|---|
| Vital Blueprint Mini | พันธมิตร | 3.00% *(รายสินค้า)* | 2.00% *(ทั้งบริษัท)* | ✅ พร้อมจ่าย |
| ทดสอบค่าคอม | มาตรฐาน | 100 บาท *(รายสินค้า)* | — | ⚠️ **ไม่มีอัตราหัวหน้าทีม** |
| แพ็กเกจ C | Matrix | 5.00% *(หมวดหมู่)* | — | 🔴 **บริษัทยังไม่ตั้งค่า Matrix — ชั้นบนจะไม่ได้เงิน** |

**นี่คือหัวใจของข้อเสนอ** — แปลง "13 ทางที่เงียบ" ในข้อ 3.4 ให้เป็นไฟเตือนที่มองเห็น
ก่อนจะมีดีลจริงเกิดขึ้น ไม่ใช่หลังจากตัวแทนทวงเงิน

### แท็บ 2 — อัตราค่าคอม (รวม #1 #2 #8 #9 #10 เข้าด้วยกัน)

**ตารางเดียว** แสดงทั้งของตัวแทนและของหัวหน้าทีม กรองด้วยชิปด้านบน:

```
[ ทั้งหมด ] [ ตัวแทนผู้ขาย ] [ หัวหน้าทีม ]        [ + เพิ่มอัตรา ]

ผู้รับ         ขอบเขต              อัตรา      ช่วงเวลา
ตัวแทนผู้ขาย   ค่าเริ่มต้นทั้งบริษัท   4.50%     22 ก.ค. 69 →
ตัวแทนผู้ขาย   สินค้า: Vital…       3.00%     19 ส.ค. 69 →
หัวหน้าทีม     ค่าเริ่มต้นทั้งบริษัท   2.00%     1 ส.ค. 69 →
หัวหน้าทีม     สินค้า: Vital…       2.50%     19 ส.ค. 69 →   ← ต้องแก้ schema
```

**ฟอร์มเพิ่มอัตรา — 5 คำถามเรียงกัน ฟอร์มเดียวใช้ได้ทุกกรณี:**

```
1. จ่ายให้ใคร      ( ) ตัวแทนผู้ขาย   ( ) หัวหน้าทีม
2. ใช้กับอะไร      ( ) ทุกสินค้าในบริษัท  ( ) ทั้งหมวดหมู่ [▾]  ( ) สินค้าเดียว [▾]
3. คิดแบบไหน       ( ) % ของยอดขาย   ( ) จำนวนเงินคงที่
4. เท่าไหร่        [____] %
5. เริ่มเมื่อไหร่    [19 ส.ค. 2569]   ถึง [ไม่กำหนด]
                                   → ต่ออายุปีถัดไป? [ตั้งค่า]
```

ข้อ 3 หายไปเองเมื่อสินค้านั้นล็อกหน่วยไว้แล้ว (พร้อมบอกว่าล็อกเป็นอะไร) —
แทนที่จะปล่อยให้กรอกแล้ว 422 ทีหลังแบบตอนนี้

### แท็บ 3 — โครงสร้างแผน

การ์ดของแต่ละแผน **เรียงตามจำนวนสินค้าที่ใช้จริง** แผนที่ไม่มีสินค้าใช้ยุบเป็นบรรทัดเดียว:

```
▸ พันธมิตร (Affiliate)   ● ใช้กับ 4 สินค้า        [ตั้งค่า]
    ช่วงเวลา attribution · โหมดจ่าย Additive/Deductive
    ⓘ อัตราหัวหน้าทีมของแผนนี้อยู่ที่แท็บ "อัตราค่าคอม" →

▸ Matrix                ● ใช้กับ 1 สินค้า  🔴 ยังไม่ตั้งค่า   [ตั้งค่า]
▸ Binary                ○ ยังไม่มีสินค้าใช้
▸ อันดับ (Stairstep)     ○ ยังไม่มีสินค้าใช้
▸ Generation            ○ ยังไม่มีสินค้าใช้
```

แก้ปัญหา 3.5/2.3 ตรง ๆ: แท็บ "พันธมิตร" ที่ไม่มีอัตรา จะ**บอกเองว่าอัตราอยู่ที่ไหน**

### แท็บ 4 — ตั้งค่าทั่วไป

- แผนเริ่มต้นของบริษัท (ย้ายมาจาก `/companies`)
- สวิตช์แบ่งคอมตัวแทนร่วม (ย้ายมาจาก `/commission-split-settings`)
- **เพดานอัตราแพลตฟอร์ม — สร้างใหม่** (Super Admin เท่านั้น)
- ลิงก์ไป Promotion (ไม่ย้าย เพราะเป็นโบนัสแคมเปญ คนละก้อน)

## สิ่งที่ต้องแก้หลังบ้าน (มีอย่างเดียว)

**เพิ่ม `product_id` + `product_category_id` (nullable) ให้ `commission_override_rules`**
แล้วให้หาอัตราด้วยลำดับเดียวกับ `commission_rules` (สินค้า > หมวดหมู่ > ทั้งบริษัท)

- แถวเดิมมี 2 คอลัมน์นี้เป็น NULL = "ค่าเริ่มต้นทั้งบริษัท" → **พฤติกรรมเดิมไม่เปลี่ยน**
- ไม่ต้องแตะ ledger, ไม่ต้อง backfill, ไม่กระทบ BR-4

**คำถามที่ต้องตัดสินใจ (BR-7 — ผมไม่ตัดสินให้):**
> อัตราหัวหน้าทีม **ยังควรผูกกับ cert tier ของหัวหน้าอยู่ไหม** ในเมื่อ ADR-035
> ตัดเหตุผลนี้ออกจากอัตราตัวแทนไปแล้ว?
> — ถ้า "ไม่" ฟอร์มจะเหลือ 5 ช่องตามที่ออกแบบไว้ข้างบนพอดี
> — ถ้า "ยัง" ต้องเพิ่มช่องที่ 6 และอธิบายให้ชัดว่าทำไมสองอย่างนี้คิดคนละแบบ

## ลำดับการทำ

| เฟส | ทำอะไร | ได้อะไร | แตะหลังบ้าน |
|---|---|---|---|
| **1** | แท็บ **ภาพรวม + ไฟเตือน** | เห็น 13 ทางเงียบก่อนเสียเงิน — **คุ้มที่สุดต่อแรง** | ✗ (อ่านอย่างเดียว) |
| **2** | ย้าย **ค่าคอมหัวหน้าทีม** เข้าแท็บอัตราค่าคอม + เพิ่มตัวเลือก **บาท** | เลิกซ่อนอยู่ในหน้าแคตตาล็อก | ✗ |
| **3** | รวมฟอร์มอัตราเป็นฟอร์มเดียว ตัดฟอร์มซ้ำใน `/product-catalog` เหลือลิงก์ | ตัดจาก 4 ฟอร์ม → 1 | ✗ |
| **4** | **อัตราหัวหน้าทีมแยกรายสินค้า/หมวดหมู่** | ตรงกับที่ขอ | ✓ migration + resolver + tests |
| **5** | โครงสร้างแผนแบบยุบ/ขยาย + หน้าเพดานแพลตฟอร์ม | ความซับซ้อนขอถึงจะเห็น | ✗ (มี endpoint แล้ว) |

เฟส 1–3 **ไม่แตะหลังบ้านเลย** — ทำได้ทันทีโดยไม่มีความเสี่ยงต่อเงินที่จ่ายไปแล้ว

## สิ่งที่ข้อเสนอนี้ **ไม่** ทำ

- **ไม่ลดจำนวนแผน** — 6 แผนยังอยู่ครบ ความหลากหลายไม่หาย เปลี่ยนแค่วิธีเข้าถึง
- **ไม่ย้าย Promotion** — เป็นโบนัสแคมเปญ ไม่ใช่ค่าคอม เดินคนละทางในโค้ด
- **ไม่แตะการแบ่งคอมรายดีล** — ตัวแทนตั้งเองในแอปตัวแทน ไม่ใช่งานแอดมิน
- **ไม่ปิดช่องโหว่เพดาน** ที่ไม่ตรวจกฎหมวดหมู่/ทั้งบริษัท — เป็นการตัดสินใจเชิงธุรกิจแยกต่างหาก
