## 2. เจอบั๊กจริงเพิ่ม 2 ตัว — แก้แล้ว

### 2.1 ไฟล์ที่ไม่มีนามสกุล → path ลงท้ายด้วยจุดเปล่า

**16 จุด**สร้างชื่อไฟล์ด้วย `Str::uuid().'.'.$file->getClientOriginalExtension()`

`getClientOriginalExtension()` อ่านนามสกุลจาก**ชื่อไฟล์ที่ client ส่งมา** และคืน
**สตริงว่าง**ถ้าไฟล์นั้นไม่มีนามสกุล → ได้ path เป็น `.../<uuid>.` ลงท้ายด้วยจุดโดด ๆ

Apache เสิร์ฟไฟล์นั้นด้วย Content-Type ที่ใช้ไม่ได้ → **เบราว์เซอร์ไม่แสดงอะไรเลย**
ทั้งที่ไฟล์อยู่ครบบนดิสก์ และไม่มี error ใน log ที่ไหนเลย — เป็นเคส
"อัปโหลดสำเร็จแต่รูปเสีย" ที่หายากที่สุด

`ModuleLessonService::safeExtension()` แก้เรื่องนี้ถูกต้องอยู่แล้วตั้งแต่ TASK-093
แต่แก้ที่เดียว **อีก 15 จุดไม่มี**

**แก้:** ยก method นั้นขึ้นเป็น `App\Support\Media\StoredFileName` แล้วให้ทุกจุดใช้ร่วมกัน

ลำดับการเลือกนามสกุล:
1. `$file->extension()` — Symfony เดาจาก **MIME จริง** (อธิบายตัวไบต์ ไม่ใช่ชื่อ)
2. นามสกุลจาก client กรองเหลือ `[a-z0-9]` (`.` / `..` จึงรอดไม่ได้)
3. `'bin'` — **ไม่มีทางเป็นสตริงว่าง** path จึงลงท้ายด้วยจุดโดดไม่ได้อีก

### 2.2 route ที่ไม่มีอยู่จริง → 500 ทั้ง endpoint

`ProductCatalogMediaResource` เรียก `route('product-catalog-media.stream')` และ
`route('product-catalog-media.thumbnail')` — **ทั้งสองชื่อไม่มีใน `routes/api.php`**

คอมเมนต์ในไฟล์เขียนว่า "ยังเข้าไม่ถึงจนกว่า route จะมี" — **ไม่จริง**
`ProductCatalogItemResource:31` ฝัง collection นี้ไว้ และ
`ProductCatalogItemController::show()` eager-load `media` อยู่แล้ว

ถ้ามีแถว `product_catalog_media` สักแถวที่ `source_type=upload` หรือมี `thumbnail_path`
→ `RouteNotFoundException` → **500 ทั้งหน้า** ไม่ใช่แค่รูปเสีย

ยังไม่เคยระเบิดเพราะ**ไม่มี controller/service ไหนสร้างแถวพวกนั้นเลย** — เป็นกับระเบิด
ไม่ใช่บั๊กที่เกิดแล้ว · **แก้โดยกั้นด้วย `Route::has()`** ไม่ใช่ลบทิ้ง: พอ TASK-213
วาง route จริงเมื่อไหร่ URL จะทำงานทันทีโดยไม่ต้องแก้ไฟล์นี้อีก

## 3. คำสั่งใหม่ — `php artisan media:audit`

ตอบคำถาม "ยังมีไฟล์ไหนพังอีกไหม" **โดยไม่ต้องไล่กดดูทีละหน้า**

รอบที่แล้วเจอเพราะ human บังเอิญเห็นโลโก้เสียใบเดียว — ไฟล์อื่นพังเท่ากันหมดแต่ไม่มีใครดู
**อาการที่หาเจอได้ด้วยการเปิดดูเท่านั้น คืออาการที่จะเจอตอนสายเกินไป**

ตรวจทุกคอลัมน์ที่เก็บ path (18 คอลัมน์ ทั้ง `public` และ `local`):

| ตรวจ | หมายความว่า |
|---|---|
| ไฟล์มีอยู่จริงบน disk | แถวชี้ไปที่ไฟล์ที่ถูกลบไปแล้ว |
| ไม่ใช่ 0 ไบต์ | เขียนไม่สำเร็จ / ถูกตัดกลางคัน |
| path ไม่ลงท้ายด้วยจุด | บั๊กข้อ 2.1 ที่ยังค้างในแถวเก่า |
| `public/storage` มีอยู่ | ต้นเหตุตอนที่ **ทุกอย่าง**พังพร้อมกัน |

```bash
php artisan media:audit                 # ทุกบริษัท
php artisan media:audit --company=1     # เจาะบริษัทเดียว
```

**อ่านอย่างเดียว 100%** ไม่ลบแถว ไม่ซ่อมอะไร ไม่แตะไฟล์ — คำสั่งที่แอบ "เก็บกวาด"
แถวที่หาไฟล์ไม่เจอ คือคำสั่งที่จะลบเอกสาร PDPA ของลูกค้าทิ้งในวันที่ดิสก์ mount ไม่ติด

รายงาน symlink กับไฟล์**แยกกันคนละบรรทัด** โดยตั้งใจ: ถ้า symlink หาย ไฟล์ทุกใบ
เข้าไม่ถึงไม่ว่าแถวจะสวยแค่ไหน สรุปรวมว่า "0 ปัญหา" จะเป็นการโกหก

## 4. ที่ยัง**ไม่**แก้ และเหตุผล

| เรื่อง | ทำไมไม่แก้ |
|---|---|
| `'throw' => false` ทั้งสอง disk | เขียนไฟล์ล้มจะคืน `false` เงียบ ๆ แทนที่จะโยน error · เปลี่ยนเป็น `true` กระทบทุกจุดที่อ่านไฟล์แบบเผื่อ ๆ ไว้ — blast radius กว้างเกินกว่าจะเปลี่ยนพร้อมงานนี้ |
| `Options +FollowSymLinks` ใน `public/.htaccess` | ตอนนี้โฮสต์ตามลิงก์ได้อยู่แล้ว (พิสูจน์แล้ว โลโก้ 200) · การใส่ `Options` บนโฮสต์ที่ `AllowOverride` ไม่อนุญาต จะทำให้ทั้งเว็บ 500 — เสี่ยงกว่าที่ได้ |
| `FFMPEG_PATH` / `PDFTOPPM_PATH` บน production | เป็นค่า config ไม่ใช่โค้ด · ถ้าไม่ตั้ง วิดีโอจะอัปได้ปกติแต่ **thumbnail เป็น null ตลอด** ซึ่งหน้าตาเหมือน "รูปเสีย" เป๊ะ · ตรวจด้วย `which ffmpeg` บนเซิร์ฟเวอร์ ถ้าไม่มีให้ตั้งค่า path ใน `.env` |
| วิดีโอข่าวสารเสิร์ฟผ่าน symlink ตรง ๆ | เป็นจุดเดียวที่ไฟล์ใหญ่ (สูงสุด 200MB) ไม่ผ่าน `RangeFileResponder` — ทำงานได้ แต่ไม่มี byte-range · เป็นงานแยก |
