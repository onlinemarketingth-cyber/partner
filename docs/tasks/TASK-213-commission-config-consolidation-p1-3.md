## เฟส 1 — ภาพรวมบอกได้ว่า "จ่ายได้จริงไหม"

`CommissionPlansView.vue` → มุมมอง **ภาพรวมสินค้า**

**แถบสรุปด้านบน** — พร้อมจ่าย N · ควรตรวจสอบ N · ต้องแก้ไข N

**การ์ดสินค้าแต่ละใบ** เพิ่ม 2 ช่องคู่กัน:

| ตัวแทนผู้ขายได้ | หัวหน้าทีมได้ |
|---|---|
| 3.00% · สินค้า: Vital… | 2.00% · จ่ายชั้นเดียว |

ช่อง "หัวหน้าทีมได้" แสดงตัวเลขเฉพาะแผน **มาตรฐาน (Unilevel)** และ
**พันธมิตร (Affiliate)** ซึ่งเป็นสองแผนที่จ่ายชั้นบนจาก
`commission_override_rules` จริง ๆ · แผนอื่นเขียนว่า "ดูที่แท็บ …"
แทนที่จะโชว์ตัวเลขที่ไม่ได้ถูกใช้

**ถ้ามีหลายอัตราตาม cert tier ของหัวหน้า จะเขียนว่า "N อัตรา (ตาม tier ของหัวหน้า)"**
ไม่ยุบเป็นตัวเลขเดียว — ยุบเมื่อไหร่คือโกหกทันที

**ไฟเตือน** แทนแบนเนอร์เหลืองเดิม:

| ระดับ | เงื่อนไข | ข้อความ |
|---|---|---|
| 🔴 | ไม่มีกฎคอมที่ resolve ได้เลย | ดีลที่ปิดได้จะไม่มีใครได้เงินเลย |
| 🔴 | แผนต้องการโครงสร้าง แต่บริษัทยังไม่ตั้ง | ตัวแทนได้ แต่ชั้นบนจะไม่ได้อะไร |
| 🟡 | Unilevel/Affiliate แต่ไม่มีอัตราหัวหน้าทีม | หัวหน้าจะไม่ได้ส่วนแบ่ง |
| 🟢 | ผ่านหมด | ตั้งค่าครบ พร้อมจ่าย |

แบนเนอร์เดิมขึ้น**ทุกใบ**ที่ใช้แผนมีโครงสร้าง ไม่ว่าจะตั้งค่าแล้วหรือยัง —
เตือนตลอดเวลาคือไม่ได้เตือนเลย อันใหม่**เงียบเมื่อทุกอย่างเรียบร้อย**

**การตรวจ (`loadReadinessProbe`)** ยิงเฉพาะ endpoint ของแผนที่มีสินค้าใช้จริง —
บริษัทที่ใช้แต่ Unilevel ไม่มี request เพิ่มเลย · error ถูกกลืน (ปล่อยเป็น
"ไม่ทราบ") เพราะตัวตรวจที่ตอบไม่ได้ต้องไม่พังหน้าที่มันแค่มาอธิบาย และต้อง
ไม่ขึ้นเตือนผิด

> **Generation ต้องมีทั้ง 2 อย่างถึงนับว่าพร้อม** — ตั้ง `max_generation_depth`
> อย่างเดียวยังจ่ายไม่ได้ ถ้าไม่มีแถวอัตรารายเจน ระบบจะ "กินโควตาเจนแล้วไม่จ่าย"
> เงียบ ๆ (อ่านจาก `GenerationCommissionService`)

## เฟส 2 — ค่าคอมหัวหน้าทีมย้ายมาอยู่หน้าเดียวกับค่าคอมตัวแทน

แท็บ **กฎคอมมิชชั่น** เปลี่ยนเป็นรายการเดียวที่กรองด้วย **ใครได้เงิน**:

```
[ ทั้งหมด ] [ ตัวแทนผู้ขาย ] [ หัวหน้าทีม ]   [+ เพิ่มอัตราตัวแทนผู้ขาย] [+ เพิ่มอัตราหัวหน้าทีม]
```

- แถวสีขาว = ตัวแทนผู้ขาย (`commission_rules`)
- แถวขอบเหลือง = หัวหน้าทีม (`commission_override_rules`)

**ความสามารถใหม่: เลือก "จำนวนคงที่ (บาท)" ให้หัวหน้าทีมได้แล้ว**
ฟอร์มเดิมส่ง `rate_type: 'percentage'` แบบตายตัวโดยไม่มีช่องให้เห็นหรือแก้
ทั้งที่ `StoreCommissionOverrideRuleRequest` รับ `fixed_satang` มาตลอด และ
`CommissionRateCalculator` ก็คำนวณได้มาตลอด — เป็นเคสธุรกิจที่รองรับอยู่แล้ว
แต่ไม่มีปุ่ม · **ยังเพิ่ม "มีผลถึง" ที่ฟอร์มเดิมไม่มี และแก้ไขแถวเดิมได้ (เดิมลบได้อย่างเดียว)**

**ทำไมยังเป็น 2 ฟอร์ม ไม่ใช่ฟอร์มเดียว 5 คำถามตามที่วาดไว้:** เพราะวันนี้
สองอันถามคนละเรื่องจริง ๆ — อัตราตัวแทนมีขอบเขต (สินค้า/หมวดหมู่/บริษัท)
และมีอัตราต่ออายุ ส่วนอัตราหัวหน้าคีย์ด้วย cert tier ของหัวหน้าและ**ไม่มีมิติ
สินค้าเลย** การยัดรวมก่อนทำเฟส 4 จะได้ฟอร์มที่ช่องของมันโกหกว่าแถวเก็บอะไรได้
ฟอร์มหัวหน้าทีมจึงเขียนบอกตรง ๆ ว่า *"อัตรานี้ยังใช้กับทุกสินค้าในบริษัท"*

## เฟส 3 — ปิดประตูที่ซ้ำ

`ProductCatalogView.vue`: แท็บ **อัตราคอมมิชชั่น** และ **ค่าคอมหัวหน้าทีม (Override)**
ถูก**ลบออกจริง** เหลือป้ายบอกทางไป `/commission-plans`

- คีย์แท็บทั้งสองยัง valid → ลิงก์เก่า `?tab=commission_rules` ยังเปิดได้
  และไปเจอป้ายบอกทาง ไม่ใช่หน้าว่าง
- ลบโค้ดที่ตายแล้วออกด้วย: ฟอร์ม, ConfirmDialog 2 อัน, `formatRate`,
  `ruleCapGuard`, interface 2 อัน และ **request 2 เส้น** (`/commission-rules`,
  `/commission-override-rules`) ที่ยิงทุกครั้งที่เปิดหน้าแคตตาล็อกทั้งที่ไม่มี
  อะไรใช้แล้ว

เหลือประตูเข้า `commission_rules` **2 ทาง** (แท็บอัตราค่าคอม + wizard) จากเดิม 4
โดย 2 ทางที่เหลือใช้ฟอร์มเดียวกัน

## QA

1. `/commission-plans` → **ภาพรวมสินค้า** → ดูแถบสรุปด้านบนและไฟเตือนของแต่ละสินค้า
   ตรวจว่าสินค้าที่ยังไม่มีกฎคอมขึ้นแดง "ไม่มีใครได้เงินเลย"
2. สินค้าที่ใช้ Matrix/Generation แต่บริษัทยังไม่ตั้งโครงสร้าง → ต้องขึ้นแดง
   พร้อมปุ่ม "ไปตั้งค่า →" ที่พาไปแท็บถูกตัว
3. **การตั้งค่าทั้งหมด → กฎคอมมิชชั่น** → กดชิป "หัวหน้าทีม" → ต้องเห็นอัตราเดิม
   ที่เคยอยู่ในหน้าแคตตาล็อก (ข้อมูลชุดเดียวกัน ไม่ใช่ของใหม่)
4. **+ เพิ่มอัตราหัวหน้าทีม** → เลือก **จำนวนคงที่ (บาท)** → กรอก 200 → บันทึก →
   รายการต้องขึ้น "200 บาท" ไม่ใช่ "2.00%"
5. กด **แก้ไข** แถวหัวหน้าทีม → ค่าต้องเติมกลับมาถูกทั้งหน่วยและตัวเลข
6. Super Admin สลับบริษัทบนหัวจอ ขณะอยู่แท็บภาพรวม → ไฟเตือนต้องเปลี่ยนตาม
   (ไม่ค้างของบริษัทเดิม)
7. `/product-catalog` → แท็บอัตราคอมมิชชั่นและค่าคอมหัวหน้าทีม**ต้องหายไป**
8. เปิด `/product-catalog?tab=override_rules` ตรง ๆ → ต้องเจอป้ายบอกทาง ไม่ใช่หน้าว่าง

## ยังเหลือ

- **เฟส 4** — `commission_override_rules` เพิ่ม `product_id` + `product_category_id`
  (nullable) เพื่อให้แยกอัตราหัวหน้าทีมรายสินค้า/หมวดหมู่ได้ตามที่ขอ
  แถวเดิม NULL = พฤติกรรมเดิม ไม่ต้อง backfill ไม่แตะ ledger
- **เฟส 5** — แท็บโครงสร้างแผนแบบยุบ/ขยาย + หน้าตั้งเพดานแพลตฟอร์ม
  (`PUT /platform/commission-cap` มีอยู่แล้วแต่ไม่เคยมีหน้าจอ)
- **คำถามที่ยังไม่ได้ตอบ (BR-7):** อัตราหัวหน้าทีมยังควรผูกกับ cert tier
  ของหัวหน้าไหม ในเมื่อ ADR-035 ตัดเหตุผลนี้ออกจากอัตราตัวแทนไปแล้ว —
  คำตอบเปลี่ยนหน้าตาฟอร์มในเฟส 4
