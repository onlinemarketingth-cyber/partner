Task: Shared UI transition/animation system (cross-cutting, both frontends)
Owner: ag-ui — executed directly by ag-lead
Goal: Establish a reusable transition pattern once, in both frontends' shared design-system layer, before Phase 4-7 add substantially more views — so every future screen inherits page/list/drawer motion and a loading skeleton for free instead of needing a retrofit pass later. Not a business-logic task; no BR/Section reference — pure UI polish, requested directly by the human after asking "would adding this now or after every phase take less time."
Related: CLAUDE.md Section 7 ("design-system components are duplicated between the two frontends, not shared via a package yet — keep both copies in sync, CI-001/CI-002")

Input: The existing design-system components (`HeroHeader.vue`, `TabFilterBar.vue`, `EmptyState.vue`, `LoadingSkeleton.vue` — the last one existed only in `frontend`, unused by any view) and the views built in Phase 1-3 (`ClientsView.vue`, `AcademyView.vue`, `AcademyManagementView.vue`, `ProductCatalogView.vue`).

Expected output:
- `frontend/src/assets/main.css` and `frontend-admin/src/assets/main.css` — identical shared transition CSS added to both (duplicated per CI-001/CI-002, same as every other design-system asset in this project): `.page-fade-*` (route transitions), `.list-fade-*` + `.list-fade-move` (list entrance, for use with `<TransitionGroup>`), `.drawer-*` (slide-in panel + fading backdrop, targeting a `.drawer-panel` child class), and a `prefers-reduced-motion` media query that force-shortens every transition/animation duration to near-zero for users who've asked their OS to reduce motion (accessibility, not optional).
- `frontend/src/App.vue` and `frontend-admin/src/App.vue` — `<RouterView>` now wraps its resolved component in `<Transition name="page-fade" mode="out-in">`, keyed by route path. This is the single highest-leverage change: every view, past and future, gets a page transition automatically with zero per-view code.
- `frontend-admin/src/design-system/components/LoadingSkeleton.vue` — ported verbatim from `frontend` (parity fix; `frontend-admin` had no loading-state component at all before this, every admin view showed a blank page during its initial fetch).
- `ClientsView.vue`, `AcademyView.vue` (frontend), `AcademyManagementView.vue`, `ProductCatalogView.vue` (frontend-admin): each now tracks a `hasLoadedOnce` ref alongside its existing `loading` ref, shows `<LoadingSkeleton type="list">` only on the very first fetch (not on every reload after a create/upload, which would blank the whole page unnecessarily), and wraps its `v-for` list(s) in `<TransitionGroup name="list-fade">` instead of a plain `<div>`.
- `ClientsView.vue`'s detail drawer: the whole `v-if` block is now wrapped in `<Transition name="drawer">`, and the inner panel element carries a `.drawer-panel` class so it slides in from the right while the backdrop only fades (CSS targets `.drawer-panel` as a descendant of the transitioning root, since Vue's `<Transition>` only applies enter/leave classes to the element it directly wraps).

Acceptance Criteria:
  - Both `frontend` and `frontend-admin` have byte-identical transition CSS in their respective `main.css` (verified by direct comparison — CI-001/CI-002 duplication discipline)
  - Navigating between any two routes in either app now fades/slides rather than hard-cutting (page-fade on `<RouterView>`)
  - `prefers-reduced-motion: reduce` collapses all transition/animation durations to ~0 — verified by reading the CSS rule, not by manual OS-level testing (out of scope for this sandbox)
  - No BR/business-value was touched — this is UI-only, no Service/Policy/Controller/migration files changed
  - Both frontends pass `eslint . --cache` (clean), `vue-tsc --build` (exit 0), and `vite build` (exit 0, `dist/` produced) — all three actually run and confirmed in this session, not just structurally reviewed
  - The four wired views (ClientsView, AcademyView, AcademyManagementView, ProductCatalogView) show a skeleton only on initial load, not on every subsequent reload after a create/upload action

Out of scope (future tasks):
  - `ReferralsView.vue`, `PipelineView.vue`, `CommissionView.vue`, `LeaderboardView.vue`, `AdminView.vue`, `AdminHomeView.vue`, `LoginView.vue` (both apps) — still have no list-entrance/skeleton wiring since they're either still placeholder screens (Referrals/Pipeline/Commission/Leaderboard) or don't fetch a list (Login, AdminHome, AdminView are mostly static/dashboard). Design notes (not in CLAUDE.md, decided here — flag if wrong):
  - Chose CSS-class-based Vue transitions over a JS animation library — zero new dependencies, matches the project's existing "plain Tailwind + a little custom CSS" style (see `LoadingSkeleton.vue`'s pre-existing shimmer keyframe, which predates this task and was left untouched).
  - `hasLoadedOnce` (rather than gating the skeleton on `loading` alone) was a deliberate choice to avoid a jarring full-page skeleton flash every time a view refetches after a create/upload action — only the very first load shows it.
