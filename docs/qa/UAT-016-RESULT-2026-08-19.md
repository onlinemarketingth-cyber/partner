## §1 สิ่งที่รันจริง และสิ่งที่ไม่ได้รัน — ขอบอกก่อน

**ผมไม่ได้ทำตามสคริปต์ UAT-016 ทุกตัวอักษร** และอยากให้รู้ว่าเบี่ยงตรงไหน

| | แผนเดิม | ที่ทำจริง | เหตุผล |
|---|---|---|---|
| บริษัท | สร้าง `UAT Commission Co` ใหม่ | ใช้ **Thai Life** บน local dev | มีดีลที่พร้อมปิดอยู่แล้วบนสินค้าที่มีอัตราหัวหน้าทีมรายสินค้า — ได้ผลตรวจเรื่องเงินเหมือนกันด้วยขั้นตอนที่น้อยกว่ามาก |
| จำนวนการขาย | 3 (1 หัวหน้า + 3 ลูกทีม) | **1 การขายจริง** | ดูด้านล่าง |
| เคสปัดเศษ (3,333 บาท) | ต้องทดสอบ | **ไม่ได้ทดสอบ** | ราคาจริง 8,900 หารลงตัว ไม่เกิดเศษ |

## §2 ผลการตรวจเงิน — ผ่าน

**ดีลที่ปิด:** ลูกค้า ikenya · ORD-00KDZTH7 · Vital Blueprint Mini + BALANZ V5 · **8,900.00 บาท**
ผู้ขาย: kreangyot test1 ohuyhannapa · หัวหน้าทีม: Thai1 Life Agent (dev)1 · แผน **พันธมิตร (Affiliate)** โหมด Additive

| ผู้รับ | ประเภท | อัตราที่ควรใช้ | คาดว่าได้ | **ได้จริง** | ผล |
|---|---|---|---|---|---|
| kreangyot test1 | ค่าคอมของตัวเอง | 3.00% (รายสินค้า) | 267.00 | **267.00** | ✅ |
| Thai1 Life Agent | ค่าคอมหัวหน้าทีม | **2.50% (รายสินค้า)** | 222.50 | **222.50** | ✅ |
| kreangyot test1 | โบนัสแคมเปญ | 10.00% (UAT-013) | 890.00 | **890.00** | ✅ |

**สิ่งที่พิสูจน์ได้จากรายการนี้**

1. **TASK-214 ทำงานจริงกับเงินจริง** — ผมสร้างอัตราหัวหน้าทีม **2.50% เฉพาะสินค้า V5** ผ่านหน้าจอ

3. แผน Affiliate จ่ายหัวหน้า **ชั้นเดียว** และโหมด Additive **ไม่หัก**ค่าคอมของผู้ขาย (267.00 เต็ม) ✅
4. โบนัสแคมเปญเป็นก้อนแยก ไม่ปนกับค่าคอม ✅

## §3 บั๊กที่เจอ — แก้แล้วทั้ง 2 จุด

### 🐞 บั๊ก 1 — Commission Ledger แยกไม่ออกว่าเงินก้อนไหนคืออะไร *(ร้ายแรงที่สุดที่เจอ)*

**อาการ:** การขาย 1 รายการเขียน ledger 3 แถว — ลูกค้าเดียวกัน สินค้าเดียวกัน วันเดียวกัน —
และหน้าจอแสดง **เหมือนกันทุกแถว** ต่างกันแค่ตัวเลข

```
ลูกค้า ikenya · Agent: Thai1 Life Agent (dev)1 · ... · อัตรา 2.50%  → 222.5 บาท
ลูกค้า ikenya · Agent: kreangyot test1        · ... · อัตรา 3.00%  → 267 บาท
ลูกค้า ikenya · Agent: kreangyot test1        · ... · อัตรา 10.00% → 890 บาท
```

**ผมเองอ่านแล้วสรุปผิดไปหลายนาทีว่า "จ่ายซ้ำให้คนเดิม"** ก่อนจะไล่โค้ดจนพบว่าแถว 890
คือโบนัสแคมเปญ 10% ซึ่งถูกต้อง — **ถ้าผมที่เพิ่งเขียนโค้ดนี้เองยังอ่านผิด คนทำบัญชีที่กระทบยอด
รอบจ่ายจริงจะอ่านผิดแน่นอน**

**ต้นเหตุ:** backend ส่ง `earned_via` และ `override_source_agent` มาให้อยู่แล้ว
(docblock ของ Resource ถึงกับเขียนว่า earned_via คือ *"the single most important field"*)
แต่หน้าจอ **ทิ้งทั้งสองค่า** ไม่เคยเรนเดอร์เลย

**แก้:** `CommissionManagementView.vue`

- ป้ายสีบอกประเภททุกแถว — **ค่าคอมของตัวเอง / ค่าคอมหัวหน้าทีม / โบนัสแคมเปญ /
  ค่าคอมปีต่ออายุ / Binary / Matrix / อันดับ / Generation**
- แถว override บอกด้วยว่า **"(จากการขายของ …)"** — เพราะช่อง Agent บนแถวนั้นคือ**ผู้รับ ไม่ใช่ผู้ขาย**
  ซึ่งเป็นจุดที่อ่านผิดง่ายที่สุดบนหน้านี้
- เพิ่มชิปกรอง **ประเภท:** แสดงเฉพาะประเภทที่บริษัทนั้นมีจริง
- ค่าที่ไม่รู้จักขึ้น "ไม่ระบุประเภท" ไม่เดาเป็น direct

### 🐞 บั๊ก 2 — ข้อความ error เป็นภาษาอังกฤษ

**อาการ:** ลองสร้างอัตราหัวหน้าทีมซ้อนทับ ระบบปฏิเสธถูกต้อง แต่ขึ้นว่า

> *"This scope (product/category/company-default) already has a team-leader override rule covering this date range."*

ทั้งระบบเป็นไทยหมด ยกเว้นบรรทัดนี้ — และเป็นข้อความที่ผมเขียนเองใน TASK-214

**แก้:** เปลี่ยนเป็นไทยทั้งของหัวหน้าทีมและ**ของตัวแทน** (อันหลังเป็นภาษาอังกฤษมาตั้งแต่แรก
ไม่ใช่ของใหม่ แต่พังแบบเดียวกัน) → *"ขอบเขตนี้ (สินค้า/หมวดหมู่/ค่าเริ่มต้นทั้งบริษัท) มีอัตรา…อยู่แล้ว"*
**ยืนยันบนหน้าจอจริงแล้วว่าขึ้นไทย**

## §4 เรื่องที่ต้องรู้ — เจอในข้อมูลจริงของคุณ 🔴

**การขาย 3 รายการที่ปิดไปแล้วเมื่อ 13 ส.ค. 2569 ไม่มีค่าคอมของผู้ขายเลย**

| ลูกค้า | สินค้า | ledger ที่มี |
|---|---|---|
| ddds | V5 (8,900) | **มีแค่โบนัสแคมเปญ 890** |
| cus name | ทดสอบค่าคอม (1,000) | **มีแค่โบนัสแคมเปญ 100** |
| ทดสอบเพิ่มลูกค้า | ทดสอบค่าคอม (1,000) | **มีแค่โบนัสแคมเปญ 100** |

**นี่คือ "ทางเงียบ" ข้อ 1 ในตารางที่ผมสรุปไว้ตอนสำรวจ ที่โผล่มาในข้อมูลจริง** — ตอน 13 ส.ค.
ยังไม่มีกฎคอมมิชชั่นที่ resolve ให้สินค้าเหล่านั้น (กฎที่เห็นตอนนี้ `มีผล 22 ก.ค.` น่าจะถูก
สร้างทีหลังแล้วย้อนวันที่) → `CommissionService` คืนค่า null เขียน log แล้วปล่อยดีลผ่าน
ตามที่ออกแบบไว้ (ห้าม block การขายเพราะตั้งค่าไม่ครบ) **โบนัสแคมเปญยิงต่างหากจึงยังจ่าย**
ทำให้ดูเผิน ๆ เหมือนมีเงินออก

**แก้ย้อนหลังไม่ได้** — ledger เป็นข้อมูลถาวร (BR-4)

### 🔧 สิ่งที่ผมสร้างเพิ่มเพื่อไม่ให้เกิดอีกโดยไม่มีใครรู้

```bash
php artisan commission:audit-unpaid-closures [--company=ID]
```

ไล่หาดีลที่ **ถึงสถานะชำระเงินครบแล้ว แต่ไม่มีแถว ledger ประเภท direct/renewal ของผู้ขาย**
พร้อมเดาสาเหตุให้ (ไม่มีกฎ / ตัวแทนไม่มี cert) · **อ่านอย่างเดียว ไม่แก้ ไม่ย้อนจ่ายให้**
เพราะจะจ่ายชดเชยไหมและอัตราเท่าไหร่เป็นการตัดสินใจเชิงธุรกิจ (BR-7) ไม่ใช่สคริปต์ซ่อม

> TASK-213 กันของรอบหน้าไว้แล้ว (ไฟเตือนก่อนมีดีล) — อันนี้คือตัวหา**ของที่เกิดไปแล้ว**
> ซึ่งเมื่อวานยังไม่มีเครื่องมืออะไรหาเจอเลย

**แนะนำให้รันทันทีบนทุกบริษัท** จะได้รู้ว่ามีมากกว่า 3 รายการนี้ไหม
